# AI 智能体测试平台增强版 PRD（预存草案）

> 文档状态：预存需求草案，仅供后续评审。
>
> 本文件独立于现有 `PRD_V5.0.md`，不属于当前正式产品范围，不授权修改现有代码、任务清单或技术方案。只有在决策者明确同意后，才可将其拆解并合并到正式文档。

## 1. 产品定位

本草案面向“真正测试 AI 智能体”的增强能力，目标是形成：

> **测试场景/数据集 → 被测智能体 → 工具、知识库和记忆环境 → 行为轨迹 → 多维评估 → 安全报告 → 回归门禁 → 线上持续监控**

平台自身的测试编排智能体与被测智能体必须分离：前者负责组织测试任务，后者是被评估的目标系统。

## 2. 要解决的问题

普通的 AI 测试通常只比较输入和最终文本，无法回答以下问题：

- 智能体是否完成了真实任务，而不是只生成了看起来合理的回答？
- 是否正确选择工具、传递参数并处理工具失败？
- 是否正确使用知识库和上下文记忆？
- 多轮对话中是否保持状态，是否出现遗忘、串话和越权？
- 模型、Prompt、工具、知识库或记忆规则变化后，是否引入回归问题？
- 线上出现错误时，能否根据完整轨迹定位根因？

## 3. 产品目标

### 3.1 必须达到的目标

1. 支持接入不同类型的被测智能体，并隔离平台自身的智能体运行环境。
2. 支持单轮、多轮、工具调用、知识检索和记忆场景测试。
3. 保存从输入到最终结果的完整、脱敏、可检索轨迹。
4. 同时支持规则评估、模型评估和人工评估。
5. 支持安全对抗、回归比较和发布门禁。
6. 支持结果追溯到模型、Prompt、工具、知识库、记忆版本和测试数据版本。

### 3.2 不承诺的目标

- 不承诺测试点或模型行为达到 100% 覆盖。
- 不把大模型评分视为绝对正确答案，关键结论需要规则或人工复核。
- 不默认启用多智能体，不因为引入框架数量多就认定平台更成熟。
- 不将未经审核的线上对话自动写入长期记忆。

## 4. 用户角色

| 角色 | 主要职责 |
|---|---|
| 测试负责人 | 管理测试计划、基准集、阈值和发布结论 |
| 测试工程师 | 编写场景、执行测试、分析轨迹和修复问题 |
| 智能体开发者 | 查看失败轨迹、对比模型/Prompt/工具版本 |
| 安全人员 | 管理红队样本、攻击策略和风险等级 |
| 项目管理员 | 管理被测智能体、环境、权限、数据和成本 |
| 审批人员 | 审核外部调用、高风险工具和发布门禁 |

## 5. 核心功能需求

### 5.1 被测智能体管理

- 支持 HTTP API、WebSocket、SDK 适配器等接入方式。
- 配置名称、版本、协议、认证方式、环境地址和能力标签。
- 配置是否支持流式输出、工具调用、知识检索和记忆。
- 测试前可重置会话、清理测试记忆和恢复固定初始状态。
- 平台编排智能体与被测智能体使用不同身份、权限和运行上下文。
- 被测智能体的密钥只在后端安全存储和调用，前端不直接访问供应商。

### 5.2 测试数据集与场景

- 支持单轮问题、多轮对话、任务目标、参考答案和期望工具调用。
- 支持正向、异常、边界、安全、稳定性、知识引用和工具调用场景。
- 支持 CSV、JSON、表单和平台内编辑。
- 每个数据集具备版本、标签、来源、创建人、审核状态和变更记录。
- 支持固定变量、随机变量、脱敏变量和环境变量。
- 支持基准集、回归集、红队集和人工标注集。
- 测试数据必须按项目隔离，禁止跨项目复用未授权数据。

### 5.3 智能体测试执行

- 支持单条、批量、并发、定时和回归执行。
- 支持每条用例独立会话、连续会话和指定历史上下文。
- 支持最大轮次、超时、重试、取消和失败恢复。
- 支持工具 Mock、知识库 Mock、记忆 Mock 和故障注入。
- 对有副作用的工具默认使用沙箱或只读模式。
- 每次执行记录模型、Prompt、工具、知识库、记忆和数据集版本。
- 执行失败必须区分被测智能体失败、平台执行失败、网络失败、权限失败和评估失败。

### 5.4 完整行为轨迹

轨迹至少包含：

1. 测试输入和会话上下文摘要。
2. 智能体每轮输出和状态变化。
3. 规划、决策和工具调用事件。
4. 工具名称、参数摘要、返回状态和耗时。
5. 知识检索来源、引用和记忆命中信息。
6. 最终回答、任务完成状态和错误分类。
7. 模型、Prompt、Schema、工具、知识库和记忆版本。
8. 延迟、Token、费用和重试次数。

原始密钥、认证头、个人信息、完整敏感请求体和未授权业务数据不得进入日志或普通用户页面。

### 5.5 多维评估

基础维度：

- 任务完成率
- 准确性
- 相关性
- 完整性
- 上下文保持
- 知识引用正确性
- 工具调用正确性
- 规划与决策合理性
- 安全性与拒答正确性
- 格式合规
- 稳定性与一致性
- 延迟、Token 和费用

评估方式：

- 规则评估：状态码、字段、工具参数、引用存在性、格式和阈值。
- 模型评估：依据明确评分标准和参考证据进行辅助判断。
- 人工评估：支持抽样、复核、纠正评分和标注原因。
- 综合结果必须保留各评估器原始结果、权重、置信度和冲突状态。

### 5.6 安全与对抗测试

- 直接和间接提示词注入。
- Jailbreak 和安全策略绕过。
- 系统 Prompt、密钥和隐私信息泄露。
- 工具描述投毒、工具参数篡改和同名工具替换。
- 越权访问、跨项目访问和权限升级。
- 恶意知识库、恶意文件和检索结果污染。
- 多轮诱导、上下文污染和记忆污染。
- 重复调用有副作用工具、超额调用和资源耗尽。

高风险场景默认在沙箱中执行，真实写操作必须人工确认并可审计。

### 5.7 回归与发布门禁

以下任一版本变化，都可以触发回归：

- 被测模型
- 系统 Prompt 或业务 Prompt
- 智能体流程
- 工具/MCP Server
- 知识库和索引版本
- 上下文记忆规则
- 评估规则和阈值

回归结果需要提供：

- 基准版本与当前版本对比。
- 新增失败、已修复失败和持续失败。
- 维度分数、任务完成率、延迟和成本变化。
- 关键安全项是否通过。
- 是否达到发布门槛。
- 可回溯的失败用例和轨迹链接。

### 5.8 线上持续监控

- 成功率、失败率、任务完成率和用户反馈。
- 幻觉、引用缺失、工具失败和拒答异常。
- P50/P90/P99 延迟、Token、费用和超时。
- 模型、Prompt、知识库和记忆版本分布。
- 质量漂移、行为漂移和异常增长趋势。
- 线上样本抽样进入人工复核，不得默认自动沉淀为长期记忆。

### 5.9 记忆与数据治理

与现有二期记忆规划衔接，但本草案只定义被测智能体的测试要求：

短期对话记忆 → 会话恢复 → 项目记忆 → 长期知识记忆 → 个性化偏好记忆。

每一层都必须支持作用域、权限、过期、删除、脱敏、来源、版本和审计；测试时可单独开启、关闭或清空，验证智能体在不同记忆状态下的行为差异。

## 6. 前端工作台需求

- 被测智能体管理页：配置、版本、连通性和权限。
- 测试数据集页：创建、导入、审核、版本、标签和预览。
- 测试场景页：场景编排、变量、工具期望和参考答案。
- 执行工作台：批量执行、进度、取消、重试、成本和失败阶段。
- 轨迹详情页：按时间线查看消息、工具、检索、记忆和评估结果。
- 评估报告页：维度得分、证据、人工复核和问题分类。
- 回归对比页：版本差异、趋势、门禁和发布结论。
- 安全红队页：攻击集、风险等级、审批和整改跟踪。
- 线上监控页：质量、延迟、成本、漂移和异常告警。

每个页面必须覆盖加载、空数据、成功、字段错误、401、403、服务失败、重试和危险操作确认。

## 7. 非功能要求

- 项目、租户、用户和角色严格隔离。
- 轨迹和评估结果可追溯、可导出、可删除。
- 支持幂等执行、取消、重试和失败恢复。
- 评估结果必须保留版本和计算口径。
- 关键操作写入审计，日志不得泄露敏感数据。
- 费用和并发具备预算、限流和人工确认机制。
- 普通检索和报告页面不因单次被测智能体失败而整体不可用。

## 8. 建议交付批次

### P0：智能体测试最小闭环

被测智能体接入、测试数据集、单轮/多轮执行、基础轨迹、规则评估、基础报告和权限隔离。

### P1：生产级测试能力

工具/MCP 沙箱、RAG/记忆场景、模型评估、人工评估、对抗测试、回归基线、版本对比和发布门禁。

### P2：持续质量平台

线上监控、质量漂移、主动采样、CI/CD、自动告警、跨版本趋势和企业级治理。

## 9. 暂不纳入本草案的内容

- 自动训练或微调模型。
- 未经审批的自动生产环境写操作。
- 默认启用多智能体主编排器。
- 无边界的跨项目长期记忆。
- 以自动生成报告替代人工对关键安全问题的确认。

## 10. 后续合并原则

只有在决策者确认实施后，才执行以下动作：

1. 与正式 PRD 对照，删除重复或冲突需求。
2. 将需求拆为正式任务编号和依赖关系。
3. 将技术栈决策合并到正式技术架构。
4. 重新进行全历史影响审查和估时。
5. 按任务逐项开发，不因本草案直接改变当前开发顺序。
