# 项目会话续接规则

每次在本目录开始新的开发会话时，必须先执行以下动作：

1. 完整读取根目录 `AGENTS.md`、本文件、`CONTRACT_ENFORCEMENT.md`、`SESSION_START_AUDIT.md`、`PROJECT_STATUS.md`、`TASKS_V5.0.md`、`PRD_V5.0.md`、`TECH_ARCH_V5.0.md`、`.env.example`，以及核心契约中登记且与当前任务相关的专项方案；不得只读取其中三份文件。
2. 执行 `start-dev.cmd`，主动恢复前后端开发服务；若端口已在监听，不重复启动。
3. 分别检查 `http://127.0.0.1:5173/` 和 `http://127.0.0.1:8000/`，向用户报告访问地址和健康状态。
4. 执行“继续开发前审计”，完整规则见 `SESSION_START_AUDIT.md`。必须将已完成任务逐项对照 TASKS、PRD、TECH_ARCH、所有适用专项方案和测试记录，检查遗漏任务、遗漏需求、依赖倒置、未完成测试及未记录变更。
5. 先向用户输出审计反馈。即使结论为“无遗漏”，也必须说明下一任务、任务边界和服务状态，并询问是否继续；用户回复“继续”或“确认”前禁止编码。
6. 如发现遗漏，优先报告遗漏项、影响和建议处理顺序，等待用户决定是补漏还是继续原计划，禁止自行跳过。
7. 用户确认后，从 `PROJECT_STATUS.md` 中记录的“下一任务”或用户指定的补漏任务继续，不重复已经完成并验证的任务。
8. 每完成一个任务及两轮测试后，立即更新 `PROJECT_STATUS.md`：完成任务、验证结果、下一任务、关键决策和更新时间。
9. 遵守任务清单的逐任务暂停规则；没有用户确认，不跨任务开发。
10. 强制执行纵向业务闭环：一个后端业务模块完成模型、服务和 REST API 后，下一项开发必须是该模块对应的前端页面、真实本地 API 联调和用户验收入口。Shell、自动化测试、Postman 或 Django Admin 均不能替代产品前端验收。
11. 只有当控制者或决策者能从工作台找到功能，并通过界面完成该模块的核心操作、看见成功/失败/无权限等反馈后，才可将业务模块标记为闭环完成并进入下一个业务模块。
12. 底层模型或服务任务可以按既定依赖逐项开发，但到该模块 REST API 完成时必须切换到对应前端闭环任务，不得因前端任务编号靠后而跳过或延后。
13. 当决策者一次性确认5个或以上任务时，编码前必须按照核心契约V5.3对全部既有前后端功能执行一次人类使用逻辑、社会认知、需求覆盖和安全权限的严格审查；发现问题必须先报告并暂停，等待决策者处理决定。
14. 批量开发每累计完成5个任务必须审查完整Git变更和新旧代码兼容性，通过专项测试、后端全量回归、迁移检查、前端构建及关键端到端路径后，创建Git提交和`checkpoint/YYYYMMDD-任务范围`附注标签，并向决策者报告哈希、标签及测试结果。
15. 若首个批量任务开始时仓库没有可信基线，必须先完成全量审查并创建带`baseline/YYYYMMDD-pre-batch`附注标签的基线提交。Git标签仅作为可追溯恢复点，未经决策者明确授权禁止回滚。
16. 每次新开发一个功能或修改一个问题，必须调用 Codex MCP/Playwright MCP 在真实本地服务和真实登录态下执行全量多维度浏览器测试，覆盖正常、空数据、字段错误、401、403、服务失败/重试、权限边界、旧数据兼容和失败恢复；必须记录 Console、Network、持久化回读及临时数据清理证据。MCP 不可用、关键场景未执行或存在未解释错误时，保持验收阻断，不得标记完成。当前任务已获确认且场景矩阵已确定时，MCP 全量边界验收可连续执行而不逐场景请求确认；该例外不改变编码、修复、完成认定、状态更新、Git、远程操作和真实外部副作用的确认门禁，最终报告仍须用户确认。

## 新增代码影响与链路回归门禁

16. 任何新增或修改的代码，在判定任务合格前必须完成影响分析：从变更文件、类、函数、接口或数据结构出发，检索并记录所有直接调用方、间接调用方、下游业务模块、REST API、前端入口和共享依赖。
17. 新增的公共代码或共享服务必须按调用链逐一验证所有已知使用方；不得只验证新增代码自身，不能以单元测试通过替代调用方兼容性证明。
18. 影响分析必须覆盖正常、空数据、字段错误、401、403、服务失败、权限边界、旧数据/旧接口兼容和回滚路径；无法确认影响范围时，必须扩大检索和测试范围，不得假定“没有影响”。
19. 每个任务完成报告必须附“变更影响矩阵”和“链路测试证据”，列出变更点、调用方、受影响功能、验证用例、结果和未覆盖风险；任一受影响链路未验证或存在未解释失败，任务不得标记完成。

如果开发服务无法启动，应读取 `.runtime/backend.log` 和 `.runtime/frontend.log`，先排查启动错误，再继续业务开发。
