# AITS 项目契约执行补充（强制）

生效日期：2026-09-04

本文件是核心开发契约的执行补充，优先级覆盖整个项目：需求分析、任务拆分、后端、前端、联调、测试、验收、修复、重构、Git 和会话续接都必须受核心契约约束。任何临时需求、效率目标或已有代码状态都不能绕过契约；冲突时以契约为准。

## 硬门禁

1. 启动新会话必须读取项目状态、任务清单、PRD、技术架构、核心契约并完成启动审计。
2. 每个任务必须按后端能力、REST API、对应前端、真实本地 API 联调、用户验收闭环；完成两轮测试后停止等待确认。
3. 发现历史违规、遗漏、兼容性问题、权限问题、交互问题、未解释失败或记录不一致时，必须先报告影响和整改顺序，暂停后续任务。
4. 决策者一次确认 5 个或以上任务时，编码前必须全历史审查；每累计完成 5 个任务必须完成 Git 兼容性审查、专项测试、全量回归、迁移检查、前端构建、关键端到端验证、提交和附注标签。
5. 没有可信基线时，首个批次前必须建立 `baseline/YYYYMMDD-pre-batch`；检查点使用 `checkpoint/YYYYMMDD-任务范围`。
6. Git 推送属于外部变更，只有决策者明确发出“推送 Git”指令时才执行；本地提交和标签按检查点门禁执行。
7. 任何违反门禁的实现均视为不合格，必须重新审查、整改、测试并记录，不能以“功能已经存在”或“测试通过”豁免。
