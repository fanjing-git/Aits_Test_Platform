## 任务执行规则

```yaml
执行规则:
  1. 每个任务执行前输出确认信息，等待用户回复
  2. 每个任务完成后必须经过两轮测试验证
  3. 复杂功能必须先输出开发计划，等待用户确认
  4. 每个任务完成后立即停止，等待用户确认
  5. 禁止跨任务编码、禁止推测用户意图
  6. 所有测试使用Mock，禁止实际计费调用
  7. 所有LLM调用必须包含重试和降级机制
  8. 基于正常社会思维和人类使用逻辑进行开发
  9. 任务ID保持稳定；当新增任务形成前置依赖时，依赖关系优先于编号顺序
  10. 🟦 每个业务模块必须按“后端能力→对应前端→前后端联调→用户验收”纵向闭环，未完成可视化验收不得进入下一个业务模块
  11. 🟪 决策者一次性确认5个或以上任务时，编码前必须全量审查此前所有前后端功能；每累计完成5个任务必须通过兼容性审查和全量测试并创建Git提交及附注标签
```

## 使用说明

```yaml
工具兼容性:
  适用于任何AI编码工具

使用方式:
  1. 保存为 TASKS_V5.0.md
  2. 在任何AI编码工具中引用
  3. 从项目状态记录的下一任务执行；依赖优先于编号，🟦 前端闭环任务紧跟对应后端模块，T111-T112属于第三期非阻断任务

执行流程:
  1. 提交任务指令
  2. AI输出确认信息
  3. 用户确认
  4. AI执行开发
  5. AI执行两轮测试
  6. AI输出完成报告
  7. 用户确认
  8. 下一任务

纵向闭环门禁:
  1. 后端接口自动化测试通过
  2. 对应前端使用真实本地API完成联调
  3. 覆盖加载、空数据、失败、无权限和成功反馈
  4. 用户可从工作台找到功能并完成核心操作
  5. 用户验收后才进入下一业务模块
```
