## 1. 产品概述

### 1.1 产品定义

AI智能体测试平台是一个**对话驱动的智能测试助手**。用户通过自然语言描述测试需求，平台智能体自主完成需求分析、用例生成、测试执行、结果分析、报告推送全流程。

### 1.2 核心差异化

- **对话即测试**：自然语言交互，无需编写测试代码
- **需求深度分析**：上传/导入需求文档，LLM深度理解并拆解功能
- **联合功能识别**：自动识别跨模块联动场景（功能A在功能C页面展示）
- **用例智能生成**：多轮对比确认，自动评审，自动筛选自动化用例
- **业务联调测试**：不仅测单接口，自动识别并测试业务链路
- **多类型测试**：接口/UI/APP/性能/AI/安全/回归/数据，共9种
- **多模型兼容**：OpenAI/Claude/Gemini/通义千问/DeepSeek等
- **四级提示词**：即时>场景>项目>全局，默认预置
- **知识持续沉淀**：含人工审核，使用越多越智能
- **主动测试建议**：Git变更/质量趋势/环境异常主动通知
- **多渠道通知**：企业微信/钉钉/邮件/平台内消息
- **测试资产复用**：用例模板、策略模板、缺陷模式跨项目复用
- **效果可度量**：ROI仪表盘、时间节省量化


## 2. 用户与场景

### 2.1 用户角色

| 角色       | 特征             | 核心诉求                  |
| ---------- | ---------------- | ------------------------- |
| 开发工程师 | 写完代码快速验证 | 快、简洁、即时反馈        |
| 测试工程师 | 系统化测试       | 全面、详细、高效生成      |
| 测试负责人 | 质量管控         | 数据、趋势、团队协作、ROI |
| 系统管理员 | 平台维护         | 配置、权限、监控          |

### 2.2 典型场景

#### 场景一：需求文档生成用例
```
测试员：[粘贴腾讯文档链接]
智能体："检测到腾讯文档《订单模块需求V2.1》，正在读取...
✅ 读取成功，识别到8个功能模块，21个功能点，3个联动场景。

接下来我将进行：
1. 需求深度分析
2. 联合功能识别
3. 测试点分析
4. 用例生成（多轮对比确认）
5. 用例评审（多轮对比确认）
6. 自动化用例筛选

预计生成50-60条用例，开始吗？"
```

#### 场景二：业务联调测试
```
测试员："帮我测完整的下单流程"
智能体："识别到业务链路：登录→浏览商品→加购物车→创建订单→支付→订单状态更新

已生成联调用例18条，包含：
- 正常流程用例6条
- 异常分支用例8条
- 边界场景用例4条

执行顺序已编排，依赖关系已标注。开始执行？"
```

#### 场景三：截图识别生成用例
```
测试员：[上传报错截图]
智能体："识别到登录页面错误提示：'系统繁忙，请稍后重试'

可能原因：
1. 后端服务超时
2. 数据库连接池耗尽

已生成验证用例4条，建议立即执行。需要我执行吗？"
```

#### 场景四：Git提交自动触发
```
开发者提交代码 → 智能体检测变更 → 分析影响范围 → 自动选择用例 → 自动执行 → 结果推送企业微信
```

#### 场景五：智能应答引导
```
用户："帮我测试"
智能体："好的，请问你想测试什么呢？接口、UI、APP还是其他类型？

如果不确定，我可以根据你最近的项目情况帮你推荐。"
```

| F1.1.1 | 文本输入     | 自然语言测试需求描述                 |
| F1.1.2 | 文件上传     | PDF/Word/Excel/Markdown/APK/IPA/截图 |
| F1.1.3 | 图片输入     | 报错截图/UI设计稿/流程图/架构图      |

| F1.1.6 | 代码粘贴     | 代码片段/接口定义/JSON数据           |

### 5.2 多轮对话

| 编号   | 功能           | 说明                                    |
| ------ | -------------- | --------------------------------------- |
| F1.2.1 | 上下文记忆     | 记住整个会话内容，不丢失信息            |
| F1.2.2 | 指代消解       | 理解"这个""它""刚才的"等指代            |
| F1.2.3 | 话题切换与回溯 | 切换话题后可回到之前任务                |
| F1.2.4 | 澄清追问       | 信息不足时主动提问，一次最多3个关键问题 |
| F1.2.5 | 确认机制       | 关键操作前向用户确认                    |

### 5.3 打断处理（三模式）

| 打断类型       | 用户表达             | 智能体行为   | 结果处理         |
| -------------- | -------------------- | ------------ | ---------------- |
| 暂停（Pause）  | "等一下"、"暂停"     | 保留中间状态 | 补充信息后可继续 |
| 停止（Stop）   | "停止"、"不要执行了" | 停止当前执行 | 保留已完成结果   |
| 取消（Cancel） | "取消"、"算了"       | 取消当前执行 | 清理临时数据     |

**响应要求**：用户在对话中输入打断指令，智能体≤3秒响应，不等待当前任务完成。

### 5.4 主动交互

| 编号   | 功能     | 触发时机            | 说明             |
| ------ | -------- | ------------------- | ---------------- |

| F1.4.2 | 风险预警 | 检测到高风险操作    | 高风险必提醒     |
| F1.4.3 | 进度通知 | 长任务关键节点      | 25%/50%/75%/100% |
| F1.4.4 | 结果提醒 | 报告生成后          | 通知用户查看     |

| 模式     | 说明                             | 默认 |
| -------- | -------------------------------- | ---- |

| 详细模式 | 每条用例实时通知                 | —    |

### 5.6 智能应答与引导

| 编号   | 功能           | 说明                                                      |
| ------ | -------------- | --------------------------------------------------------- |
| F1.6.1 | 不合理输入识别 | 识别信息不足/目标模糊/逻辑矛盾/范围过大/信息冲突/不切实际 |
| F1.6.2 | 澄清追问       | 像人一样追问关键信息                                      |
| F1.6.3 | 建议式引导     | 用户不确定时主动分析推荐                                  |
| F1.6.4 | 风险确认       | 高风险操作前明确确认                                      |
| F1.6.5 | 友好拒绝       | 不合理/不合规请求友好拒绝+替代方案                        |
| F1.6.6 | 对话自然性     | 像同事交流，不机械不模板                                  |

**对话风格要求**：自然、简洁、有温度、专业、主动、不越界

**不合理输入处理示例**：
```

用户："测那个东西" → 智能体："抱歉，我没理解'那个东西'指什么，能具体说明吗？"
用户："测生产环境随便造数据" → 智能体："生产环境测试需谨慎，建议先在test环境验证。"

```

## 7. F3 任务管理系统

### 7.1 任务生命周期

```
创建 → 规划中 → 待确认 → 排队中 → 执行中 → 分析中 → 报告生成 → 已完成
  │       │        │        │        │        │          │        │
  └───────┴────────┴────────┴────────┴────────┴──────────┴────────┘
                         任意状态可打断（暂停/停止/取消）
```

### 7.2 任务类型

| 类型         | 说明                 | 触发方式     |
| ------------ | -------------------- | ------------ |
| 即时测试     | 一次性快速验证       | 用户对话发起 |
| 完整测试     | 系统化全流程         | 用户对话发起 |
| 定时回归     | 定时自动执行         | 用户设定时间 |
| Git触发      | 代码提交自动触发     | Git Webhook  |
| 主动建议触发 | 智能体主动建议后执行 | 用户确认建议 |

### 7.3 执行排队机制

| 场景         | 处理方式                   |
| ------------ | -------------------------- |
| 单人多个任务 | 按触发时间排队             |
| 多人同时触发 | 按用户优先级+时间排队      |
| 资源不足     | 提示排队位置和预计等待时间 |
| 紧急任务     | 测试负责人可提升优先级插队 |
| 用户取消排队 | 取消后不消耗资源           |

### 7.4 错误恢复机制

| 场景           | 恢复方式                  |
| -------------- | ------------------------- |
| 网络中断       | 自动重试3次，失败标记     |
| 环境不可用     | 暂停+通知+恢复后可继续    |
| LLM调用失败    | 自动降级到备用模型        |
| 代码生成失败   | 自动重新生成，标记原因    |
| Celery任务崩溃 | 自动重新入队，最大重试3次 |
| 数据库连接失败 | 自动重连，失败通知管理员  |

| 🟧 可观测性 | 🟧 记录Server、工具、调用者、参数摘要、耗时、结果状态和审批记录，敏感值必须脱敏 |
| 🟧 失效处理 | 🟧 超时、断连、能力变化和协议不兼容时安全失败，不得静默改用高权限工具 |

### 11.5 Skills扩展与第三方兼容

平台必须同时支持内置 Skill、项目自定义 Skill 和经审核的第三方 Skill。自定义 Skill 不能只保存配置，必须能够绑定受控运行时实现，并经过输入输出契约校验后由智能体调用。

第三方 Skill 来源至少兼容本地 Skill 包、GitHub 仓库、SkillHub 地址和可下载的版本化包。所有来源必须记录来源地址、版本、提交哈希或文件哈希、作者、许可证、安装人、审核人和安装状态；禁止未审核代码直接执行。

第三方 Skill 安装必须经过管理员审批，支持版本锁定、启用/停用、卸载和回滚。Skill 必须声明网络、文件、数据库、外部命令、模型、知识库和环境凭据权限，默认拒绝高风险权限；运行时必须执行项目隔离、超时、资源限制、错误隔离和审计记录。

第三方来源不可用、内容校验失败、权限超出审批范围或运行时异常时，平台必须安全失败，并保留内置 Skill 和已批准本地 Skill 的正常使用能力。Skill 来源适配、安装和运行权限必须通过平台前端可见、可审计、可撤销。

## 23. 开发路线图

### 🟦 23.0【V5.2 已人工确认】纵向业务闭环交付
