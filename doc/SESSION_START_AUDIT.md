# 继续开发前审计

每次重新启动 Codex CLI 或开始新的开发会话时，必须在编写代码前完成本审计。审计属于只读检查，不得借审计名义修改业务代码。

## 一、进度一致性

1. 读取 `PROJECT_STATUS.md` 的已完成任务和下一任务。
2. 对照 `TASKS_V5.0.md` 的任务表与依赖关系图，确认：
   - 已完成任务不存在依赖缺失；
   - 编号之间没有被遗漏且应优先完成的前置任务；
   - 新增任务已写入任务总数、阶段列表和依赖关系；
   - 下一任务确实满足全部前置依赖。
3. 对照实际文件与测试结果，确认状态文件没有把未实现或未验证内容标记为完成。
4. 检查最近完成的 REST API 是否已经紧跟对应前端页面和真实 API 联调；若尚未形成控制者/决策者可操作的验收入口，必须把对应前端闭环列为下一任务，不得进入其他业务模块。
5. 检查当前授权是否为一次性确认5个或以上任务；若是，必须先执行核心契约V5.3全历史严格审查，并确认仓库存在可信Git基线、最近检查点与标签记录一致。
6. 检查自上一个Git检查点以来已完成任务数；批量开发累计达到5个任务时，必须先完成兼容性审查、全量测试、Git提交和附注标签，不得继续第6个任务。

## 二、PRD 需求覆盖

1. 在 `PRD_V5.0.md` 中定位下一任务所属功能及验收要求。
2. 对照 `TECH_ARCH_V5.0.md` 的模块、接口、数据模型和技术约束。
3. 检查已完成相关任务是否遗漏 PRD 明确要求，尤其关注：
   - 正常流程、边界、异常、安全和权限场景；
   - 前后端入口与 API 是否能够形成可操作链路；
   - 控制者或决策者是否能从工作台进入功能、完成核心操作，并看见加载、空数据、成功、失败和无权限反馈；
   - 配置、迁移、依赖和环境变量是否已同步记录；
   - 两轮测试是否有证据，是否仍有失败或警告未处理。
   - 新代码是否改变既有API契约、迁移、配置、路由、权限、异常语义或用户路径，以及这种改变是否经过兼容性验证。

## 三、运行状态

1. 运行 `start-dev.cmd`。
2. 检查正式入口 `http://127.0.0.1:5173/`。
3. 检查后端健康接口 `http://127.0.0.1:8000/api/health/`。
4. 若失败，先查看 `.runtime/backend.log` 与 `.runtime/frontend.log` 并报告原因。

## 四、强制反馈格式

```text
会话启动审计结果

服务状态：前端[...]；后端[...]
当前完成进度：[最后完成任务]
任务遗漏检查：[无遗漏 / 遗漏列表]
PRD需求遗漏检查：[无遗漏 / 遗漏列表]
测试与记录检查：[完整 / 问题列表]
批量任务与Git检查点：[未触发 / 已完成全历史审查；最近提交与标签]
建议处理顺序：[建议]
下一任务：[任务ID、名称、边界、依赖]

是否继续？
```

只有用户明确回复“继续”或“确认”后，才能开始修改代码。如果发现遗漏，反馈中必须说明继续原任务可能产生的影响。
