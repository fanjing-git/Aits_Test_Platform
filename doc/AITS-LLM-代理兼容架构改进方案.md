# AITS v5 LLM 统一连接与跨地域部署架构改进方案（第二期）

> 文档状态：二期评审稿，暂不作为开发完成依据
>
> 版本：2.0-draft
>
> 日期：2026-09-09
>
> 适用范围：AITS v5 后端、Celery Worker、模型配置前端、LLM 运行时和部署环境

## 1. 评审结论

### 1.1 总体判断

本需求不应作为第一期的必做内容。第一期应优先保证国内模型在当前服务器上的可用性，并完成真实出网诊断、错误分类和前端可理解反馈。

本方案的完整目标是：

1. 同一套 AITS 代码支持国内受限网络环境；
2. 支持管理员配置经批准的第三方代理或转发服务；
3. 支持部署到境外自有服务器后直接访问官方模型 API；
4. 支持国内、境外、混合部署之间迁移，而不修改业务模块代码；
5. 在直连、代理和自建境外出口之间提供可审计、可验证、可回滚的连接选择。

这已经不是“给模型增加一个代理 URL”这么简单，而是一个“LLM 连接配置、协议适配、网络策略和跨地域部署”的基础架构能力，应作为第二期独立建设。

### 1.2 一期与二期边界

| 内容 | 一期 | 二期 |
|---|---|---|
| 国内模型直连 | 必须完成 | 继承 |
| 服务器真实出网诊断 | 必须完成 | 继承并扩展 |
| 自定义模型 ID | 支持保存，标记未验证 | 支持按连接配置验证 |
| 第三方代理 | 暂不建设通用架构 | 建设受控代理连接 |
| 境外自有服务器直连 | 按现有 direct 模式工作 | 纳入部署配置和验收矩阵 |
| 直连/代理自动切换 | 不做 | 谨慎支持，默认关闭 |
| 多协议适配 | 使用现有能力 | 统一抽象并补齐协议边界 |
| 多连接、故障转移、审计 | 不做 | 按本方案建设 |

### 1.3 本期明确不做的事情

二期也不承诺以下内容：

- 自动保证所有代理商支持所有模型；
- 自动绕过供应商地区限制、账号限制或额度限制；
- 把所有供应商都强行转换为 OpenAI 兼容协议；
- 对推理 POST 请求进行无条件跨通道重试；
- 在普通用户界面暴露代理商 API Key；
- 通过任意用户填写的 URL 访问内网、云厂商元数据地址或未审核的外部站点；
- 通过硬编码模型列表保证代理服务长期可用；
- 仅依靠 TCP 探测结果判断一次模型调用必然成功。

## 2. 现状与问题判断

### 2.1 当前系统现状

当前模型配置仍以供应商和 API 地址为核心，主要字段包括 `provider`、`model_name`、`api_key_encrypted` 和 `api_base_url`。现有出网校验已经包含供应商域名白名单、HTTPS、端口、DNS 解析、私网地址和重定向限制。

相关实现位于：

- `backend/apps/configs/models.py`：模型配置和密钥加密；
- `backend/apps/configs/services.py`：供应商目录、出网地址验证和模型发现；
- `backend/apps/requirement_analysis/llm_adapter.py`：现有共享 LLM 运行入口；
- `backend/core/llm/manager.py`：模型管理和运行时工厂；
- `frontend/src/views/ModelConfigView.vue`：模型配置和目录同步入口；
- `frontend/src/utils/modelConnection.js`：连接错误分类和用户提示。

技术架构和任务清单中已经要求后端、Celery Worker 分别验证出网能力。因此，代理和境外部署不能只在 Django Web 容器中实现，必须覆盖所有实际发起模型请求的进程。

### 2.2 网络结论必须以实测为准

不能把“某个云地域无法访问 OpenAI”扩大成“所有境外供应商都无法访问”。当前已知实测中，OpenAI 曾出现 TCP 超时，而 DeepSeek 和 Anthropic 能够建立连接并返回认证或权限类响应。这说明：

- TCP 可达和 API 鉴权是两个不同问题；
- 不同云厂商、地域、出口和时间段的结果可能不同；
- 供应商目录显示失败，不等于模型配置逻辑错误；
- 防火墙入站 HTTPS 规则不能解决服务器访问外部 API 的出站问题。

因此，系统必须记录失败阶段，而不能只返回“供应商不可用”。

## 3. 核心架构原则

### 3.1 供应商、协议、连接和部署环境分离

模型调用至少包含四个概念：

```text
模型供应商 Provider
    例如 OpenAI、Anthropic、DeepSeek、Qwen

调用协议 Protocol
    例如 OpenAI Compatible、Anthropic Messages、Google Native

连接配置 Connection Profile
    例如 OpenAI 官方直连、国内批准代理、境外自有出口

部署环境 Deployment Environment
    例如中国大陆云主机、境外云主机、开发机
```

代理商不是模型供应商。除非某个代理服务有完全不同的协议、鉴权方式、模型目录和能力声明，否则不应把 `api2d`、`aiproxy` 等直接加入 `ModelConfig.Provider`。

推荐的关系是：

```text
ModelConfig
  ├─ provider: 模型供应商
  ├─ model_name: 上游模型 ID
  ├─ connection_profile: 连接配置
  └─ capability_requirements: 能力要求

ConnectionProfile
  ├─ channel: direct | proxy | self_hosted
  ├─ protocol: openai_compatible | anthropic_messages | google_native
  ├─ base_url
  ├─ encrypted credential
  ├─ provider allowlist / endpoint policy
  ├─ health status
  └─ data residency / compliance metadata
```

### 3.2 境外自有服务器是一等部署模式

境外自有服务器不能被视为“一个特殊代理 URL”。它具有独立的运维和安全特征：

- 可以直接访问官方供应商；
- 可能承担统一出口、日志、限流和费用控制；
- 可能通过私有网络连接 AITS 主站；
- 可能只允许 AITS 后端访问，不对公网开放；
- 可能需要 mTLS、固定出口 IP 或内部鉴权；
- 可能运行自建 OpenAI-compatible Gateway，也可能运行供应商原生协议适配层。

因此，二期应支持两类“境外自有服务器”模式：

1. **远程 LLM Gateway**：AITS 访问自建网关，网关再访问官方 API；
2. **AITS 部署在境外**：AITS 后端和 Worker 直接访问官方 API。

两者都使用连接配置抽象，但网络拓扑、密钥保存位置、健康检查和审计要求不同，不能只通过修改 `base_url` 区分。

### 3.3 默认显式选择，自动切换必须受控

连接选择默认采用显式配置：

- `direct`：只使用官方或批准的直接端点；
- `proxy`：只使用指定代理或 Gateway；
- `self_hosted`：只使用指定的自建境外连接；
- `auto`：二期后续能力，默认关闭。

自动切换只允许在满足以下条件时发生：

- 管理员显式开启；
- 备用连接与当前模型的协议和能力兼容；
- 失败原因属于 DNS、TCP、TLS、连接超时等网络类错误；
- 当前请求是目录查询、健康检查或明确可安全重试的幂等请求；
- 发生切换时写入审计日志和请求诊断信息。

以下错误不得自动切换：

- 401、403：密钥或权限问题；
- 400、404：请求格式或模型不存在；
- 409：上游状态冲突；
- 429：额度或限流问题；
- 内容安全拒绝、上下文超限、能力不支持；
- 业务请求已经被上游接受但客户端未收到完整响应的情况。

推理类 POST 请求不得默认跨通道重试，以避免重复扣费、重复执行或结果不一致。

## 4. 二期需求范围

### 4.1 连接配置管理

新增独立的连接配置实体，暂定名为 `ConnectionProfile`。最终名称以实现评审为准。

至少包含：

| 字段 | 说明 |
|---|---|
| `name` | 管理员可识别名称 |
| `channel` | `direct`、`proxy`、`self_hosted` |
| `protocol` | 调用协议类型 |
| `provider_scope` | 支持的供应商范围 |
| `base_url` | 经过校验的端点地址 |
| `credential_encrypted` | 独立加密的连接密钥 |
| `model_id_prefix` / 映射 | 可选的模型 ID 转换规则 |
| `capabilities` | 文本、视觉、工具调用、Embedding 等能力 |
| `is_active` | 是否允许业务使用 |
| `is_verified` | 是否通过连接测试 |
| `last_health_status` | 最近健康状态 |
| `last_health_checked_at` | 最近检查时间 |
| `data_region` | 数据处理区域或未知 |
| `admin_note` | 管理员备注 |

不建议在每个 `ModelConfig` 中重复保存代理 URL 和代理密钥。连接配置应可被多个模型复用，便于轮换密钥、统一停用、统一审计和统一健康检查。

### 4.1.1 连接配置审批生命周期

第三方代理、自建境外 Gateway 和境外服务器连接必须经过独立审批，不能因为管理员能够填写 URL 或密钥，就直接进入生产调用。

连接配置至少经过以下状态：

```text
草稿 → 待审核 → 审核通过 → 已验证 → 已启用
                  ├→ 已拒绝
                  ├→ 已暂停
                  └→ 已撤销
```

- 新建的 `proxy`、`self_hosted` 或跨地域 `direct` 连接默认为“待审核”；
- 审核通过只表示治理和权限允许，不代表端点已经连通；
- 已验证必须由与线上相同身份的 Django 和 Celery Worker 完成安全连接测试；
- 只有审核通过、已验证、已启用且当前用户/项目有权限时，连接才可用于业务调用；
- 连接过期、暂停或撤销后，所有引用模型必须停止调用或切换到明确批准的备用连接；
- 审批超时默认拒绝，不得自动放行。

审核申请必须记录连接类型、端点和地域、协议、供应商范围、模型和能力范围、数据去向、第三方留存策略、密钥归属、预计费用、额度、允许的租户/项目/环境/角色、连接测试结果、申请人、审核人、有效期和撤销原因。

审批规则：

- 普通用户不能创建、修改或启用任意外部连接；
- 平台管理员负责连接创建、域名/IP 白名单和凭据管理；
- 生产数据、敏感数据、跨地域传输或高费用连接必须触发 Human-in-the-Loop 审批；
- 高风险连接原则上需要双人确认，创建人不能审批自己的高风险连接；
- 修改端点、协议、地域、凭据归属、数据范围或费用策略必须重新审核；
- 网络健康失败不自动改变审批状态，但必须阻止调用并通知管理员；
- 创建、提交、批准、拒绝、启用、停用、暂停、撤销、切换和密钥轮换都必须进入审计链。

### 4.2 端点安全校验

所有直连、代理和自建 Gateway 都必须经过统一安全校验：

- 仅允许 HTTPS，除非是明确标记为开发环境的本地连接；
- 禁止环回地址、私网地址、链路本地地址、云元数据地址和保留地址；
- 禁止通过重定向绕过域名校验；
- 对域名、解析结果和最终连接地址进行校验；
- 官方供应商使用供应商白名单；
- 第三方代理和自建 Gateway 使用管理员维护的域名或出口白名单；
- 禁止普通用户创建任意外部连接；
- 连接测试不能回显完整 API Key；
- 日志中不得记录请求头、密钥、完整 Prompt 或敏感响应。

自建境外服务器若使用固定 IP，应通过管理员审批的 IP 白名单接入，不能因此取消 SSRF 防护。

### 4.3 协议适配

连接配置必须声明协议，不能假设所有上游都支持：

```text
openai_compatible
  /models
  /chat/completions
  可选 embeddings、responses、tools、vision

anthropic_messages
  /models
  /messages
  Anthropic 版本头和原生字段

google_native
  Gemini 原生路径、鉴权和响应结构
```

代理如果只支持 OpenAI-compatible 协议，只能被绑定到支持该协议的模型配置。不能因为代理目录中显示了 Claude 或 Gemini，就假定当前运行时已经支持这些模型。

### 4.4 模型目录和模型 ID

模型目录分为三类：

1. **实时目录**：连接测试成功后从端点获取；
2. **参考目录**：用于没有实时目录能力时辅助填写；
3. **用户自定义模型 ID**：允许保存，但状态为未验证。

参考目录不能作为模型可用性的承诺，也不能硬编码价格、免费额度或永久模型列表。代理可能进行模型重命名、隐藏模型、按账号授权模型或增加前缀，系统必须支持模型 ID 映射和原始 ID 保存。

### 4.5 健康检查和错误诊断

连接测试至少区分以下阶段：

```text
配置格式
  → DNS
  → TCP
  → TLS
  → HTTP 状态
  → 鉴权
  → 目录能力
  → 指定模型能力
```

错误响应应包含稳定的错误码、面向用户的提示和面向管理员的诊断信息。至少包括：

- `invalid_endpoint`
- `dns_failed`
- `tcp_blocked`
- `tls_failed`
- `proxy_unavailable`
- `auth_failed`
- `permission_denied`
- `model_not_found`
- `capability_not_supported`
- `quota_exhausted`
- `provider_http_error`
- `invalid_response`
- `internal_error`

后端和 Celery Worker 必须分别进行连接验证，因为两个进程的网络、环境变量和代理配置可能不同。

### 4.6 前端产品要求

普通用户的核心任务是选择可用模型，不是管理网络代理。因此：

- 代理商、Gateway、境外出口配置只对管理员或决策者开放；
- 普通用户只看到“可用模型”和“连接状态”；
- 连接配置页面要显示当前通道：官方直连、代理、自建境外出口；
- 显示数据将经过第三方服务的合规提醒；
- 目录同步失败时仍允许管理员保存自定义模型 ID；
- 保存成功不等于连接验证成功，界面必须区分“已保存”和“已验证”；
- 对网络失败、Key 错误、模型不存在、权限不足和服务端异常提供不同提示；
- 提供重试和重新测试入口，不要求用户反复提交密钥。

## 5. 部署和运行要求

### 5.1 进程覆盖范围

以下进程必须使用同一套连接解析和安全校验逻辑：

- Django Backend；
- Celery Worker；
- Celery Beat 中涉及模型健康任务的部分；
- 未来独立的 LLM Gateway 或模型任务进程。

不能只修改 Web 请求路径而遗漏异步任务。环境变量、证书、系统代理和出口策略也不能假定会自动传递给所有容器。

### 5.2 三种部署模式

#### 模式 A：国内服务器 + 国内模型

- 使用官方国内模型端点；
- 连接配置为 `direct`；
- 不依赖第三方代理；
- 作为一期和二期的最小可用基线。

#### 模式 B：国内服务器 + 经批准的代理或自建境外 Gateway

- AITS 仅连接经过管理员审批的 Gateway；
- Gateway 的密钥和 AITS 的管理权限分离；
- 连接配置为 `proxy` 或 `self_hosted`；
- 明确 Prompt、文件、测试数据可能经过第三方或境外服务。

#### 模式 C：境外服务器 + 官方 API 直连

- AITS 后端和 Worker 部署在境外网络环境；
- 连接配置为 `direct`；
- 使用官方供应商端点和密钥；
- 通过部署验收矩阵验证 Backend、Worker、目录查询和实际推理均可用。

#### 模式 D：国内控制面 + 境外 LLM 执行面

这是后续可选扩展，不作为二期首个交付目标。需要额外设计：

- 控制面与执行面的认证；
- 任务和 Prompt 的跨地域传输；
- 数据脱敏和传输加密；
- 任务重试和幂等；
- 跨地域日志和审计；
- 境外执行节点的注册、撤销和健康状态。

如果二期发现必须采用模式 D，应单独立项，不能隐藏在“代理 URL 兼容”任务中。

## 6. 安全、合规和运营要求

### 6.1 密钥管理

- 每个连接配置独立加密保存密钥；
- 代理密钥、官方密钥、自建 Gateway 密钥不得默认复用；
- 支持密钥轮换而不影响模型配置引用；
- 禁止 API 响应、异常和前端状态中回显密钥；
- 连接删除、停用和密钥轮换必须有管理员审计记录。

### 6.2 数据流和合规

使用第三方代理或境外服务器时，Prompt、需求文档、测试用例、附件和模型响应可能离开当前地域。产品必须在启用连接前明确：

- 数据经过哪个区域；
- 是否经过第三方；
- 供应商是否保存请求数据；
- 哪些项目或租户允许使用该连接；
- 是否允许敏感数据发送；
- 发生故障时是否可以切换到另一地域。

对于企业数据，连接配置必须支持项目、租户或权限范围限制，不能全局开放后再依赖用户自觉。

### 6.3 成本和可观测性

每次模型调用至少应记录不可逆或脱敏后的：

- 模型配置 ID；
- 连接配置 ID；
- 实际通道；
- 协议类型；
- 上游供应商；
- 请求耗时；
- 错误阶段和错误码；
- Token 或费用信息（供应商支持时）。

否则无法判断是官方直连、第三方代理还是自建境外出口产生了成本，也无法定位故障和重复调用。

## 7. 二期实施拆分

二期不应按“增加字段 → 写几段切换代码 → 联调”实施，而应按以下任务拆分：

| 阶段 | 交付内容 | 关键门禁 |
|---|---|---|
| P2-1 | 连接配置和协议模型设计 | 通过数据模型、权限和兼容性评审 |
| P2-2 | 端点安全校验和连接测试 | SSRF、DNS、TLS、重定向测试通过 |
| P2-3 | 统一连接解析器 | Backend、Worker 使用同一实现 |
| P2-4 | OpenAI-compatible 代理和自建 Gateway | 国内服务器真实调用通过 |
| P2-5 | 境外服务器 direct 部署验收 | 目录、鉴权、推理、异步任务全部通过 |
| P2-6 | Anthropic/Google 等协议适配 | 仅对实际支持的能力开放 |
| P2-7 | 管理员前端、审计和合规提示 | 失败、重试、权限和脱敏验收通过 |
| P2-8 | 有限制的备用连接能力 | 不重复扣费、不掩盖鉴权错误 |
| P2-9 | 文档、迁移、回滚和运维手册 | 生产演练通过 |

二期数据库迁移必须在开发环境生成并提交，生产环境只执行已审查的迁移。不能在生产容器中临时执行 `makemigrations` 作为部署步骤。

## 8. 验收标准

### 8.1 功能验收

- 同一个模型配置可以绑定不同连接配置，而不修改业务模块代码；
- OpenAI-compatible 代理可以完成目录查询和实际推理；
- 境外自有服务器可以作为 direct 或 self-hosted 连接使用；
- Anthropic、Google 等非 OpenAI 协议不会被错误地当作 OpenAI 请求；
- 自定义模型 ID 可以保存并明确显示未验证状态；
- 连接停用后所有引用它的模型都能得到明确错误提示。

### 8.2 网络和安全验收

- DNS、TCP、TLS、HTTP、鉴权和模型能力错误可区分；
- Backend 和 Worker 分别通过连接测试；
- 任意私网、环回、元数据地址和未授权域名均被拒绝；
- 重定向不能绕过端点安全策略；
- 密钥不出现在日志、异常、前端响应和健康检查结果中；
- 代理密钥和官方密钥可以独立轮换；
- 普通用户无法创建或读取管理员连接凭据。

### 8.3 故障和计费验收

- 网络失败可以按策略切换，认证和模型错误不会被掩盖；
- 推理 POST 失败不会无条件重复发送到备用通道；
- 连接切换会产生可追踪的审计事件；
- 可查询实际使用的通道、连接配置和上游供应商；
- 代理不可用时，用户可以看到可操作的替代方案。

### 8.4 前端闭环验收

必须按以下顺序完成真实浏览器联调：

```text
页面入口
→ 连接配置 API
→ 目录成功
→ 目录空数据
→ 自定义模型
→ 字段错误
→ 401/403
→ 网络失败
→ 代理失败
→ 重试
→ 实际模型调用
→ 后端和 Worker 一致性
→ 前端构建复核
```

任意关键步骤失败，不得标记二期完成。

## 9. 风险和决策记录

### 9.1 高风险决策

1. 是否允许第三方代理承载生产数据；
2. 是否允许普通租户使用跨地域连接；
3. 是否建设国内控制面与境外执行面的模式 D；
4. 是否允许自动备用连接；
5. 代理和自建 Gateway 的责任边界、SLA 和费用归属。

这些事项不能由开发实现自行决定，必须由产品、架构、安全和运营共同确认。

### 9.2 供应商和价格信息处理原则

不在核心架构文档中固化 API2D、AIProxy 等具体供应商的价格、免费额度、稳定性评级或永久模型清单。这些内容会变化，且可能受账号、地域和合同影响。

具体供应商应使用单独的《连接服务评估表》记录：

- 服务商资质和数据政策；
- 可用地域；
- 协议兼容性；
- 模型覆盖；
- 延迟、成功率和限流；
- 费用和结算；
- 密钥和日志政策；
- 退出和迁移成本。

### 9.3 失败回滚原则

二期上线后若连接解析异常，应能够：

- 关闭新连接配置；
- 将模型恢复到原有 direct 行为；
- 停用自动切换；
- 回滚数据库迁移或使用兼容字段；
- 保留原有模型配置和密钥，不要求用户重新录入。

## 10. 最终建议

本文件作为二期开发任务候选文档，待产品和架构评审通过后再拆入 `TASKS_V5.0.md`。在评审通过前：

- 不新增 `channel`、`proxy_base_url` 等生产字段；
- 不把 API2D、AIProxy 等写入正式 Provider 枚举；
- 不实现自动直连转代理；
- 不把“代理可用”当成“模型可用”；
- 不修改当前一期国内模型和真实出网验收边界。

一期的判断标准是“当前部署环境能否稳定使用已批准的国内模型”；二期的判断标准才是“同一套系统能否在国内代理、自建境外 Gateway 和境外直连部署之间安全迁移”。
